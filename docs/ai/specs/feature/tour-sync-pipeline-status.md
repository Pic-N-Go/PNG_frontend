# 기능 스펙 — 관광정보 동기화 파이프라인 상태 표시

## 1) 기능 정보

- 기능명: tour-sync-pipeline-status
- 관련 도메인: admin, spot
- 대상 플랫폼: iOS / Android 관리자 화면

## 2) 문제와 목표

- 기존 관리자 화면은 일반 Spot 동기화의 단일 진행률만 표시해 후속 반려동물·무장애 작업의 상태를 구분할 수 없다.
- 전체·지역·샘플 동기화 실행 후 일반 Spot → 반려동물 → 무장애 여행정보의 단계별 상태와 진행률을 한 화면에서 확인할 수 있게 한다.

## 3) 범위

- 포함:
  - 기존 `GET /admin/tour-api/sync/status` 응답의 `jobId`, `overallStatus`, `spot`, `pet`, `accessibility` 연동
  - 단계별 대기·진행·재시도·완료·실패 상태 표시
  - 진행 건수, 진행률, 상태 메시지와 단계 오류 표시
  - 상태 조회 실패 시 재조회 UI
  - 구버전 단일 진행률 응답에 대한 기존 UI 폴백
- 제외:
  - 반려동물 상세정보 수동 동기화 API와 별도 실행 버튼
  - 무장애 상세정보 수동 동기화 API와 별도 실행 버튼
  - 동기화 실행 API 계약 변경

## 4) 사용자 시나리오

- 관리자가 전체·지역·샘플 동기화를 실행하면 상태 카드가 3초 간격으로 갱신된다.
- 각 단계는 `PENDING → IN_PROGRESS → COMPLETED` 순서로 표시되며 재시도 중에는 `RETRYING`, 최종 실패 시 `FAILED`가 표시된다.
- 모든 단계가 끝나면 전체 상태가 완료로 바뀌고 최근 완료 시각과 작업 ID가 유지된다.

## 5) 데이터/API 요구사항

- 조회 API: `GET /admin/tour-api/sync/status`
- 인증: 관리자 Bearer 토큰
- 단계 상태: `PENDING | IN_PROGRESS | RETRYING | COMPLETED | FAILED`
- 폴링: 실행 중 3초, 대기·완료 상태 10초

## 6) 수용 기준

- [ ] AC1: 일반 Spot·반려동물·무장애 단계의 상태와 메시지가 각각 표시된다.
- [ ] AC2: 진행 중인 단계는 진행률과 처리 건수를 표시하고 완료 후에도 최종 결과를 유지한다.
- [ ] AC3: 재시도·실패 상태와 `lastError`가 해당 단계에 표시된다.
- [ ] AC4: 상태 조회 실패 시 화면이 깨지지 않고 재조회할 수 있다.
- [ ] AC5: 반려동물·무장애 수동 동기화 API는 추가하지 않는다.

## 7) 검증

- TypeScript 및 ESLint 통과
- 샘플 동기화 실행 후 3단계 상태 변화 수동 확인
- 완료 응답, 상태 조회 실패, 구버전 응답 폴백 확인
