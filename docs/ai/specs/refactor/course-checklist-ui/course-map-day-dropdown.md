# 기능 스펙 — course-map-day-dropdown

## 1) 기능 정보

- 기능명: 코스 확대 지도의 Day 전환을 드롭다운으로 교체하고 전체 보기·경로 요약 카드 추가
- 담당자: `@yeni`
- 관련 이슈: 없음
- 관련 도메인 (필수): `courses`
- 대상 플랫폼: iOS / Android

## 2) 문제와 목표

- 해결하려는 문제:
  1. 우측 상단 Day 세그먼트가 가로 pill 목록이라 Day가 늘어날수록 화면 밖으로 밀려났다. 390dp 기준 DAY 3까지만 보이고 4일차부터 잘렸고, 지도 위라 가로 스와이프가 팬 제스처와 충돌했다.
  2. 좌측 상단 `DAY N 경로`가 배경 판 없이 핑크 텍스트로 지도 위에 얹혀 밝은 지역에서 읽히지 않았다. 세그먼트에 이미 `DAY 1`이 있어 같은 말을 두 번 했다.
  3. 특정 Day만 보는 화면이라 여러 Day를 한눈에 비교할 방법이 없었다.
- 사용자 가치: 일수와 무관하게 일정한 조작, 지도 위 어디서나 읽히는 경로 정보, 전체 일정 한눈에 보기
- 완료 기준(한 줄): Day 수가 2일이든 15일이든 헤더 모양이 동일하고, 전체 보기에서 Day별 경로가 색으로 구분되며, 경로 정보가 하단 카드로 항상 읽힌다

## 3) 범위

- 포함(In Scope):
  - `src/screens/home/MapScreen.tsx` (`mode === 'plan-view'`) — Day 드롭다운, 전체 옵션, 하단 요약 카드, 빈 Day 처리
  - `src/constants/dayColors.ts` (신규) — Day 색 팔레트 공용화
  - `src/utils/distance.ts` — `getCourseStats()` 분리
  - `src/screens/travel/TravelPlanScreen.tsx` — 미니맵을 선택 Day만 렌더, Day 유실 방어
- 제외(Out of Scope):
  - 데이터/API 변경 — 코스 상세 응답(`GET /courses/{id}`)이 이미 모든 Day의 스팟을 `dayNumber`와 함께 내려주므로 추가 엔드포인트가 필요 없다. 거리·시간도 좌표 기반 프론트 계산이다.
  - 6일 이상 여행에서 팔레트 5색이 순환해 DAY 1과 DAY 6이 같은 색이 되는 문제 (아래 11번 참고)

## 4) 사용자 시나리오

- 시나리오 A — Day 전환
  - Given: 2일 코스의 확대 지도를 열었다
  - When: 우상단 드롭다운에서 `DAY 2`를 선택한다
  - Then: 목록이 닫히고 지도가 DAY 2의 경로·핀으로 교체되며, 해당 Day 범위로 카메라가 맞춰지고 하단 카드가 `DAY 2 경로`로 갱신된다
- 시나리오 B — 전체 보기
  - Given: 드롭다운을 열었다
  - When: 최상단 `전체`를 선택한다
  - Then: 모든 Day의 경로·핀이 각자의 Day 색으로 동시에 그려지고, 번호는 Day별로 1부터 다시 매겨진다. 카메라는 전체 스팟을 포함하는 범위로 맞춰지고 카드는 `전체 경로 / 스팟 N곳 · Nkm · N일`을 표시한다
- 시나리오 C — 빈 Day
  - Given: 스팟이 0개인 Day가 있다
  - When: 그 Day를 선택한다
  - Then: 경로·핀이 그려지지 않고 카드 메타가 `등록된 스팟이 없어요`로 대체된다. 아이콘 박스는 채도를 낮추되 카드 자체에 `opacity`는 주지 않는다

## 5) UI/UX 요구사항

- 참조 목업 파일: 없음 (기존 화면 개선)
- 트리거(닫힌 상태): 폭 `normalize(132)` 고정 · 높이 42 · radius 14 · 흰 배경 · 좌측 Day 색 점 · 라벨 `FONT_MD` · 우측 셰브런. 헤더 행 우측에 배치해 뒤로가기 버튼과 한 줄 정렬
- 목록(열린 상태): 트리거 아래 6px, 같은 폭. 행 높이 44. 최상단에 `전체` 고정 + 아래 구분선 1개 (Day 행 사이에는 구분선 없음). 5행(220) 초과 시 목록만 세로 스크롤. 열리면 스크림(`rgba(0,0,0,0.12)`) 탭으로 닫히고 우측 줌·현재위치 컨트롤은 숨긴다
- 하단 요약 카드: `left/right 16`, `bottom normalize(40)`, radius 16, 흰 배경. 좌측 36 아이콘 박스(`IconRoute`) + 제목 `FONT_MD` + 메타 `FONT_SM`
- 빈 상태/에러 상태: 스팟 0개 Day는 카드 메타를 안내 문구로 대체. 지도 로드 실패는 기존 동작 유지
- 로딩 상태: 별도 처리 없음 (지도 데이터는 파라미터로 전달받아 즉시 렌더)

## 6) 데이터/API 요구사항

- 사용 API: 없음 (신규 호출 없음). 확대 지도는 `TravelPlanScreen`이 넘긴 `route.params.planData`를 쓰고, 원본은 `src/api/courses.ts`의 `getCourse()`

## 9) 수용 기준 (Acceptance Criteria)

- [x] AC1: Day 수와 무관하게 닫힌 드롭다운 폭이 고정이고, 6행 이상이면 목록만 스크롤된다
- [x] AC2: 전체 보기에서 Day별 경로·핀이 서로 다른 색으로 그려지고 번호는 Day별 1부터 시작한다
- [x] AC3: 지도 위 자유 배치 텍스트가 제거되고, 경로 정보는 하단 카드에서 읽힌다
- [x] AC4: 스팟이 가까운 Day에서 과확대되지 않고, 가장자리 핀이 헤더·카드에 가리지 않는다
- [x] AC5: 코스 보기에서 마커가 클러스터로 묶이지 않는다 (클러스터 배지가 단색이라 Day 색·번호를 덮음)

## 10) 테스트 시나리오

- 정상 케이스: 1일 / 2일 / 6일 코스에서 Day 전환·전체 보기, 하단 카드 값 일치
- 경계 케이스: 스팟 0개 Day, 스팟 1개 Day(폴리라인 없음), 스팟 2곳이 3km 이내인 Day(과확대), 6행 이상 목록 스크롤, 팔레트가 순환하는 6일차
- 실패 케이스: 좌표가 없는 스팟이 섞인 Day, 일정이 줄어 선택 중이던 Day가 사라진 경우(1일차로 클램프)

## 11) 오픈 이슈 / 결정 필요

- **Android 드롭다운 터치 미검증.** 목록을 헤더 안에 두면 부모 높이를 넘는 자식이 되어 안드로이드에서 터치가 전달되지 않는다. 루트 형제로 분리해 해결했으나 실기 확인이 남았다.
- **6일 이상 여행의 색 순환.** 팔레트가 5색이라 DAY 1과 DAY 6이 같은 색이고 번호도 둘 다 1부터 시작해 전체 보기에서 구분이 불가능하다. 색을 늘리는 것은 해법이 아니며(북마크 컬렉션 팔레트와 공유), 필요 시 핀 라벨에 Day 접두를 붙이는 방식(`D1-1`)으로 전환한다. 대부분의 코스가 1~3일이라 현재는 보류.
- **요약 카드와 줌 컨트롤의 우측 정렬.** 카드는 `normalize(16)`, 컨트롤은 raw `16`이라 430dp 기기에서 2px 어긋난다.

## 12) 구현 시 문서와 달라진 결정

원본 지시 문서 대비 아래는 의도적으로 다르게 구현했다.

| 항목 | 문서 | 구현 | 이유 |
|---|---|---|---|
| 트리거 위치 | 지도 위 `right:16, top:16` | 헤더 행 우측 | 뒤로가기 버튼과 한 줄 정렬, 겹침 계산 불필요 |
| 선택 상태 색 | 고정 핑크 `rgba(227,27,89,0.06)` | Day 팔레트의 `bg`/`text` | 문서 §5의 "Day 색으로 맞춘다"를 따름. 미니맵도 이미 Day별 색 |
| 점 슬롯 폭 | 8 고정 | `normalize(16)` 고정 | 8이면 겹친 3개 점이 라벨을 밀어 전체 행과 Day 행의 라벨 시작선이 어긋남 |
| 비선택 행 점 | `rgba(0,0,0,0.15)` | 원래 Day 색 유지 | 이 점이 지도 경로 색의 범례라 회색으로 죽이면 정보가 사라짐 |
| 카드 `bottom` | 16 | `normalize(40)` | 카카오 로고·축척을 가리지 않기 위함(문서 §3의 목적) |
| 핀 번호 | (a)/(b) 선택 | (a) Day별 1부터 | 현재 규모에서 겹침이 없음 |
