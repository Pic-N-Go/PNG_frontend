# 기능 스펙 — course-list-empty-state

## 1) 기능 정보

- 기능명: 출사 계획 목록의 빈 상태 정리 및 로딩·에러 상태 추가
- 담당자: `@yeni`
- 관련 이슈: 없음
- 관련 도메인 (필수): `courses`
- 대상 플랫폼: iOS / Android

## 2) 문제와 목표

- 해결하려는 문제:
  1. 아이콘이 뜻과 맞지 않았다. 사방 화살표 글리프(`IconZoomPan`)는 "드래그해서 옮기기" 관용 기호로 빈 목록과 무관하다.
  2. 96 회색 박스에 옅은 아이콘(`rgba(0,0,0,0.18)`)이 들어 있어 아이콘보다 박스가 먼저 회색 덩어리로 읽혔다.
  3. 타이포 위계가 없었다. 제목 19 / 설명 15 / 버튼 18로 세 값이 비슷하고, 제목·버튼이 `fontWeight: '700'`으로 프로젝트 상한(600)을 넘었다.
  4. 계획이 0개인데 필터 칩 4개(`전체 0 · 진행 중 0 · 예정 0 · 지난 출사 0`)가 빈 상태보다 먼저 보였다. 누를 수 있는 게 없다.
  5. 헤더 우측 `+`와 CTA가 같은 동작이라 한 화면에 중복됐다.
  6. 로딩·에러 상태가 없어 첫 진입 시 빈 화면이 그대로 노출됐다.
- 사용자 가치: 첫 사용자가 "막힌 화면"이 아니라 "시작점"으로 인식, 불필요한 컨트롤 제거, 상태별 적절한 피드백
- 완료 기준(한 줄): 계획 0개 / 로딩 / 에러 / 탭 필터 결과 0개가 각각 구분되어 표시된다

## 4) 사용자 시나리오

- 시나리오 A — 계획 0개
  - Given: 계획을 한 번도 만들지 않았다
  - When: 출사 탭에 진입한다
  - Then: 필터 칩 줄과 헤더 `+`가 보이지 않고, 화면 중앙에 아이콘·제목·설명·CTA만 있다
- 시나리오 B — 탭 필터 결과 0개
  - Given: 계획이 2개 있고 모두 `예정` 상태다
  - When: `지난 출사` 탭을 선택한다
  - Then: 칩은 그대로 유지되고 `이 조건에 맞는 출사 계획이 없어요` + `전체 보기` 액션이 표시된다 (첫 사용자용 CTA가 아님)
- 시나리오 C — 로딩·에러
  - Given: 목록을 처음 불러온다
  - When: 응답을 기다린다 / 요청이 실패한다
  - Then: 카드 스켈레톤 3개가 보이고, 실패 시 같은 레이아웃에 `목록을 불러오지 못했어요` + `다시 시도`가 표시된다. 이때도 필터 칩은 숨긴 채로 둔다

## 5) UI/UX 요구사항

- 참조 목업 파일: 없음 (기존 화면 개선)
- 아이콘: `IconMap` `normalize(34)` `#E31B59` · 박스 72 / radius 20 / `rgba(227,27,89,0.07)` 핑크 틴트 (계획 상세의 스팟 빈 상태와 같은 계열, 한 단계 큼)
- 타이포: 헤더 `FONT_2XL`/w600 · 제목 `FONT_LG`/w600 · 설명 `FONT_MD`/`rgba(0,0,0,0.5)` · 버튼 라벨 `FONT_MD`/w600
- 간격: 아이콘→제목 20, 제목→설명 8, 설명→버튼 24
- 버튼: `alignSelf: 'stretch'`로 컨테이너 패딩(40)에 맞춤 · 52 / radius 26 · `IconPlus` + 라벨
- 배치: 남은 영역을 `flex: 1`로 채우고 중앙 정렬, `paddingBottom: 100`으로 시각 중심을 살짝 올림
- 빈 상태/에러 상태: 위 시나리오 A·B·C 참고
- 로딩 상태: `src/components/common/Skeleton.tsx` 3개, 높이 `normalize(220)`, radius `CARD_RADIUS`

## 6) 데이터/API 요구사항

- 사용 API: `src/api/courses.ts` — `getCourses()`
- 요청/응답 핵심 필드: `id` · `title` · `startDate` · `endDate` · `spots`
- 실패 처리 방식: **`isError`가 아니라 `isLoadingError`로 분기한다.** TanStack Query는 캐시된 데이터가 있어도 백그라운드 요청이 실패하면 `status`를 `error`로 올린다. 이 화면은 `useFocusEffect`로 포커스마다 refetch하므로, `isError`로 분기하면 계획이 여러 개 있는 사용자가 불안정한 네트워크로 재진입할 때 목록 전체가 에러 화면으로 덮인다.
- 캐싱/무효화 전략: `queryKey: ['courses']`. `TravelNewScreen`이 생성 후 invalidate. 캐시가 아직 `[]`인 동안 첫 사용자용 문구가 스치지 않도록 로딩 조건에 `isFetching && plans.length === 0`을 포함한다.

## 11) 오픈 이슈 / 결정 필요

- **설명 텍스트 대비.** 지시 문서가 `rgba(0,0,0,0.28)`(2.6:1)의 WCAG 미달을 근거로 `0.5`로 올렸으나, `0.5`도 흰 배경에서 **3.95:1**로 본문 최소 기준(4.5:1)에 미달한다. `0.6`이면 5.74:1로 충족한다. 담당자 판단으로 문서 값 `0.5`를 유지 중 — 접근성 기준을 맞추려면 후속 논의 필요.
- **빈 상태·로딩·에러 3종 실기 미검증.** 계획이 0개인 계정이 필요하다. 확인용으로 `src/components/common/DevStateSwitch.tsx`를 임시로 붙여 상태를 전환할 수 있다(`__DEV__` 가드 내장).
- **`ContestAllEntriesScreen`의 `Placeholder`와 중복.** 아이콘·제목·설명·CTA 구조가 거의 같아 공용 컴포넌트로 추출할 후보다. 이번 범위에서는 하지 않았다.
