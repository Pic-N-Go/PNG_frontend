# Filelist Updater Skill

`scripts/filelist-data.json`의 진행 상태(uiStatus/apiStatus/date/note)를 카테고리 → 파일 선택 방식으로 갱신하고, `pnpm filelist`로 `src/html/filelist.html`을 재생성하는 스킬입니다.

## 목적

- 담당 파일을 직접 찾아 JSON을 손으로 편집하는 대신, 카테고리 → 파일 → 필드 순서로 골라 상태값을 반영한다.
- 편집 후 `pnpm filelist` 실행과 두 파일(JSON + HTML) 동시 커밋을 빠뜨리지 않도록 안내한다.

## 입력

- `scripts/filelist-data.json` (수정 대상, `_how_to_update` 키는 안내문이므로 제외)
- 사용자 입력: 아래 두 모드 중 하나
  - **일괄 입력 모드**: `<rel path> 필드=값 [필드=값 ...]` 형식 한 줄당 한 파일. 여러 줄(여러 파일) 가능. `date`는 생략하면 자동으로 오늘 날짜가 들어간다(아래 date 자동 채우기 참고) — 명시하면 그 값을 그대로 쓴다.
    예: `auth/login.html apiStatus=완료` / `spot/spot-list.html uiStatus=진행중 note=디자인 확정 반영`
  - **대화형 모드**: 카테고리 → 파일 → 필드 → 값을 하나씩 선택 (일괄 입력이 없을 때 fallback)

### date 자동 채우기
`uiStatus`/`apiStatus`/`note` 중 하나라도 바뀌는 파일은, 사용자가 `date`를 명시적으로 지정하지 않는 한 `date`를 오늘 날짜로 자동 갱신한다. 오늘 날짜는 `date +%F` 커맨드로 구한다(세션당 한 번만 실행해 재사용). date만 단독으로 바꾸는 경우(예: 대화형 모드에서 date만 선택)는 자동 채우기 대상이 아니라 사용자가 입력한 값을 그대로 쓴다.

### AskUserQuestion 옵션 4개 초과 시 페이지네이션 + 뒤로가기
`AskUserQuestion`은 질문당 옵션이 최대 4개다. 실제 항목은 페이지당 최대 3개만 담고, 4번째 슬롯은 내비게이션 전용으로 예약한다.
- 아직 안 보여준 항목이 남아 있으면 4번째 슬롯 = `더 보기` (다음 3개 + 내비게이션 슬롯으로 이어지는 새 `AskUserQuestion`).
- 더 보여줄 항목이 없으면(마지막 페이지) 4번째 슬롯 = `◀ 이전 단계로` (카테고리/파일/필드 중 바로 전 단계로 돌아가기).
- "Other" 자유 입력에 숨기지 않고 방향키만으로 모든 항목 + 뒤로가기에 도달할 수 있게 한다.
- 각 단계(카테고리/파일/필드/값) 진입 시에도 항목이 3개 이하라면 남는 슬롯에 `◀ 이전 단계로`를 넣어 언제든 되돌아갈 수 있게 한다.
- 뒤로가기를 고르면 해당 단계의 입력을 버리고 바로 전 단계 질문을 다시 띄운다 (카테고리 단계에서 뒤로가기는 없음 — 첫 단계이므로).

## 동작 규칙

### 0. 모드 판별
사용자 입력(또는 `$ARGUMENTS`)에 `<rel path> 필드=값` 패턴이 하나라도 있으면 **일괄 입력 모드**로 처리한다. 없으면 **대화형 모드**(1~4단계)로 진행한다.

### 일괄 입력 모드
a. 각 줄을 `rel path`와 `필드=값` 목록으로 파싱한다.
b. `rel path`가 JSON에 없는 키면 해당 줄만 실패로 표시하고 나머지는 계속 처리한다.
c. `uiStatus`/`apiStatus` 값이 `미시작`|`진행중`|`완료`가 아니면 해당 줄만 실패로 표시한다 (질문으로 되묻지 않는다 — 일괄 모드의 목적은 왕복 없이 빠르게 반영하는 것).
d. `date`를 명시한 줄은 `YYYY-MM-DD` 또는 빈 문자열만 허용, 아니면 실패 표시. `date`를 명시하지 않은 줄은 위 date 자동 채우기 규칙을 적용한다.
e. 유효한 줄들만 Edit로 한 번에 반영한다.
f. `pnpm filelist`는 모든 줄 처리 후 **한 번만** 실행한다.
g. 성공/실패 줄을 모두 출력 (실패 줄은 사유 포함).

### 대화형 모드
1. `scripts/filelist-data.json`을 Read하고, `_how_to_update`를 제외한 키를 `/` 기준 첫 세그먼트로 묶어 카테고리 목록을 만든다 (예: `auth`, `community`, `home`, `mypage`, `spot`, `travel`, `wishlist`).
2. `AskUserQuestion` 툴로 카테고리 목록을 options에 담아 하나를 고르게 한다 (마크다운 목록으로 출력하고 텍스트 답장을 기다리지 않는다). 카테고리가 4개를 넘으면 위 페이지네이션 규칙을 적용한다.
3. `AskUserQuestion` 툴로 선택한 카테고리에 속한 파일 목록을 options에 담아 대상 파일을 고르게 한다. 각 option의 description에 현재 uiStatus/apiStatus/date/note를 요약해 넣는다. 파일이 4개를 넘으면 위 페이지네이션 규칙을 적용하고, `◀ 이전 단계로`를 고르면 2단계(카테고리 선택)로 돌아간다.
4. `AskUserQuestion` 툴로 변경할 필드(uiStatus/apiStatus/note — `date`는 기본 제외, 직접 지정하고 싶을 때만 옵션에 노출)를 고르게 한다 (multiSelect 허용 — 여러 필드를 한 번에 바꿀 수 있음). `◀ 이전 단계로`를 고르면 3단계(파일 선택)로 돌아간다.
   - `uiStatus`, `apiStatus`를 선택한 경우: `AskUserQuestion`으로 `미시작`|`진행중`|`완료` 중 하나를 고르게 한다 (자유 입력 금지). 여기서도 `◀ 이전 단계로`를 고르면 4단계(필드 선택)로 돌아간다.
   - `note`를 선택한 경우: 자유 입력값을 텍스트로 받는다 (빈 문자열 허용).
   - `date`를 직접 지정하지 않으면 위 date 자동 채우기 규칙에 따라 오늘 날짜로 채운다.
5. Edit로 해당 파일 항목만 수정한다 (다른 항목은 건드리지 않는다). 이 시점에는 `pnpm filelist`를 아직 실행하지 않는다 — 세션 끝에 한 번만 실행한다.
6. `AskUserQuestion`으로 "더 변경하시겠어요?"를 묻는다.
   - `같은 카테고리에서 다른 파일` → 3단계(같은 카테고리의 파일 목록)로 돌아간다.
   - `다른 카테고리` → 2단계(카테고리 목록)로 돌아간다.
   - `아니요, 마무리` → 공통 마무리로 진행한다.
   - 세션 동안 수정한 파일이 쌓이면(2개 이상), 매번 이렇게 하나씩 도는 대신 일괄 입력 모드 문법을 안내해 전환을 유도할 수 있다.

### 공통 마무리
7. `pnpm filelist`를 실행해 `src/html/filelist.html`을 재생성한다 (일괄 모드는 위 f에서 이미 1회 실행했으면 중복 실행하지 않는다. 대화형 모드는 세션 전체에서 이 시점에 정확히 한 번만 실행한다).
8. `git status`로 `scripts/filelist-data.json`과 `src/html/filelist.html` 둘 다 변경됐는지 확인하고, 두 파일을 함께 커밋하라고 안내한다 (실제 커밋은 사용자 승인 후에만 실행).

## 출력 형식

```
1) 변경 내역 (세션 중 누적된 모든 파일)
   - 파일: <rel path>
     - <필드>: <이전 값> → <새 값>
   (일괄 모드에서 실패한 줄은 별도로 "✗ <rel path>: <실패 사유>" 형식으로 표시)

2) 재생성 결과
   - pnpm filelist 실행 결과 (성공/실패)

3) 커밋 안내
   - git status 상 변경 파일 목록
   - 커밋 대상: scripts/filelist-data.json, src/html/filelist.html
```
